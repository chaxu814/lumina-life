① 它们本质上是四种东西
Lumina（你的项目）
住在电脑里的多 Agent 小团队：Lumina 出面、热茶审码、Yak 分析；有情绪、有群聊、能动手操作电脑的桌面伙伴 + 办公 Agent。
N.E.K.O 猫娘计划
情感数字生命：实时语音视觉、五维记忆、五种 Avatar 形态、主动陪伴；已上 Steam + 创意工坊，主打零配置开箱。
AIRI
复刻 Neuro-sama 的 AI VTuber / 数字灵魂容器：会真的玩 Minecraft、Factorio；Web 技术栈，浏览器/桌面/iOS 都能跑。
OpenClaw
跑在设备上、接进你常用聊天软件的通用 AI 助手网关（Gateway），不是陪伴角色；389k stars 的超级社区项目。

④ 逐个对手：Lumina 的赢面与短板
vs N.E.K.O（最直接的对手）
Lumina 占优：
· 多 Agent 分工流水线，用户只见 Lumina 一个人格
· 安全沙箱/审批/注入防护更深
· 办公工具面更宽（56 个工具实现 + CLI/API）
· Agent 间"职场群像"层次更多（群聊/朋友圈/梦境/真人秀/任务游戏化）

Lumina 落后：
· 成熟度差一个量级：对方已上 Steam + 创意工坊 + 用户社区，Lumina 未公开发布
· Avatar 仅 Live2D 且现在只剩 Mao；对方 5 形态 + 动捕
· 全双工实时语音打磨、零配置"奶奶级"开箱体验
· 跨设备同一人格、14+ 供应商与免费模型、UGC 分发闭环
vs AIRI（不同赛道：VTuber/游戏）
Lumina 占优：
· 桌面办公生产力（CUA、文件/终端/代码工具链）
· 中文场景与本土渠道（QQ/钉钉）
· 情感 + 团队社交层是 AIRI 没有的
· 安全治理意识更强

Lumina 落后：
· 没有"AI 真的会玩游戏"这张王牌（MC/Factorio 智能体）
· 无 VRM；无浏览器/PWA/iOS 触达
· 工程模块化差距：对方是 monorepo + 可复用 npm 包（xsai、unspeech、DuckDB 驱动等）
· 无本地推理栈（CUDA/Metal candle、WebGPU）；国际化与贡献者社区
vs OpenClaw（不同物种，别正面打）
Lumina 占优：
· 人格化、情绪、Avatar、消费级陪伴——OpenClaw 明确不做
· 中文本土体验与桌面宠物形态

差距悬殊：
· 工程/社区不在一个量级（389k stars、8.9 万提交、3065 贡献者、日更、240 个发布）
· 8+ 成熟消息渠道、配对安全、沙箱、暴露处置手册
· 网关化 / 团队部署 / headless / Docker / Nix 全形态

建议：像 N.E.K.O 那样用 A2A 把 OpenClaw 当"手脚"调用，而不是重造一个网关。
Lumina 的真正优点
  1. 差异化概念独一份："用户只见 Lumina、后台三人团队流水线"，三家都没有。
  2. 生命感层次最丰富：情绪影响行为、Agent 间亲密度演化、群聊/早安/朋友圈/梦境/真人秀。
  3. 伙伴产品里少见的安全纵深：7 级×8 类、审批流、注入防护，达到 Agent 产品的安全意识。
  4. 集成度高：记忆/CUA/88+ 工具/MCP/技能商店/CLI/REST/渠道/游戏化在一个壳里。
  5. 本地优先、数据自持，AGPL/Apache 双许可对商业友好。
  6. 约 1 个月写出约 11 万行自有代码且有 58-case CUA 测试，交付密度高。
问题与风险（直说）
  1. 广度 > 深度：electron/ 顶层 90+ 模块（luckyMode、loop、mission、timeCapsule、dream、realityShow…），单点对拼时都不够深。
  2. 成熟度断层：4 次提交、无公开 Release、无外部贡献者、文档以内部中文为主。
  3. 形象内容单薄：删掉 Hiyori 后只剩 1 个 Live2D 模型，无 VRM/MMD/动捕。
  4. 形态单一：Win 优先的 Electron，缺 Web/PWA/移动/Server/Docker。
  5. 仓库卫生：pet-poc 自带 node_modules、.cowork-temp 参考克隆、verify-* 草稿与生产同树，主 bundle 11MB。
  6. 跟随者风险：五维记忆/猫爪/neko 音等与 N.E.K.O 重合度高，差异点必须讲得更锋利。
⑤ 建议的下一步（按优先级）
1. 把"多 Agent 团队 + 后台群像生活"磨成唯一尖刀，冻结边缘模块，做一条能病毒传播的演示视频。
2. 与强者集成：A2A 对接 OpenClaw 干硬任务；参考 xsai 统一供应商层；补 VRM 支持。
3. 模型内容补到 2–3 个授权清晰的形象，或做一键导入 / UGC（目前只剩 Mao）。
4. 仓库治理：electron 单体拆分、草稿与 pet-poc 移出发布树、补 CI 与发布流水线。
5. 尽快发一个打磨过的公开 Release + 社区入口，用真实迭代换反馈，而不是继续堆功能。
