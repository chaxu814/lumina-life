# Federation E2EE + P2P 架构设计（提案3, Level 3）

> **状态：未实现，隐私红线。**
> 本文档只描述目标架构，不包含任何可运行代码。在端到端加密（E2EE）真正落地并经过安全评审之前，
> **不要**把真实个人记忆通过公共记忆池（`docs/templates/memory-pool-worker.js`）传输——
> 那个池子是明文 KV，仅适合脱敏后的公开记忆。

## 1. 为什么需要 E2EE

Level 2 的公共记忆池（Cloudflare Workers + KV）是「服务器可读」的：运营者/平台能看到全部明文。
对于 AI 桌面伙伴这类产品，记忆里包含用户的偏好、关系、情绪记录——这是最敏感的数据。
目标形态是：**只有交换双方能解密，中继服务器只看到密文。**

## 2. 威胁模型

- **攻击者**：公共中继服务器运营者、网络中间人、拿到服务器磁盘的人。
- **假设可信**：用户自己的设备、双方之间已经带外建立的初始信任（如扫码互加）。
- **目标**：中继只能看到密文与公钥元数据，不能还原记忆内容；传输过程被篡改能被检测。

## 3. 密钥交换：X3DH（扩展 Triple Diffie-Hellman）

借鉴 Signal 协议的 X3DH，在首次连接时为双方派生一把共享会话密钥：

1. 每台设备长期持有：
   - 身份密钥对 `IK`（长期签名）
   - 预签名密钥对 `SPK`（定期轮换）
   - 一次性临时密钥 `OPK`（一次性，用完即焚）
2. Alice 首次给 Bob 发记忆包时：
   - 从公开目录取 Bob 的 `IK_B, SPK_B, OPK_B`
   - 本地生成临时临时密钥 `EK_A`
   - 做四次 DH：`DH(IK_A, SPK_B)`、`DH(EK_A, IK_B)`、`DH(EK_A, SPK_B)`、`DH(EK_A, OPK_B)`
   - 拼接后用 HKDF 派生 `32 字节主密钥 SK`
3. 后续消息用对称 ratchet（Double Ratchet）持续轮换，支持前向保密。

> MVP 取舍：第一版可以先只做「一次性预共享密钥 + 静态 X25519 静态密钥」，
> 不做 Double Ratchet——但必须在 UI 上明确标注"未启用前向保密"。

## 4. 对称加密

- 算法：**AES-256-GCM**（与 WebDAV 同步模块保持一致），或升级为 ChaCha20-Poly1305。
- 每个记忆包单独生成随机 `iv`（12 字节），密文尾部带 GCM 认证标签（16 字节）。
- 密钥不直接落盘：用用户口令 `PBKDF2(scrypt)` 派生本地主密钥，主密钥再包裹各会话密钥。

## 5. 传输层：libp2p

- 传输走 **libp2p**（WebRTC / WebSocket 打通浏览器与桌面），不绑定单一云厂商。
- 中继（relay）只做「打洞失败时的密文转发」，不参与密钥协商。
- 节点发现：
  - 方案 A（简单）：手动交换 `多地址 + 公钥指纹`，像加 IRC 好友。
  - 方案 B（进阶）：用已签名的 DHT 记录发布公钥，公钥指纹做信任锚。

## 6. 记忆包格式（加密前）

复用 Level 1 的 `MemoryExport` 结构，整体加密：

```
outer envelope = {
  version: 1,
  senderKey: base64(IK_A 公钥),
  usedPrekey: base64(SPK_B 标识),
  iv: base64(12B),
  ciphertext: base64(AES-256-GCM(序列化 MemoryExport)),
  tag: base64(16B)
}
```

接收方用自己的私钥 + X3DH 派生出的 SK 解 GCM，校验 tag 失败即判定篡改。

## 7. 落地路线（建议，但未排期）

| 阶段 | 内容 | 验收 |
|------|------|------|
| 0 | 现状：明文公共池（Level 2） | 仅传脱敏记忆，UI 红字警告 |
| 1 | 单设备端加密（WebDAV 那套） | 已在提案4实现 |
| 2 | 双设备手动共享公钥 + 静态 X25519 加密包 | 两设备互通，中继不可读 |
| 3 | X3DH + 预密钥轮换 | 新设备加入无需重新带外交换 |
| 4 | libp2p 直连 + 中继打洞 | 不依赖固定服务器 |
| 5 | Double Ratchet 前向保密 | 单密钥泄露不影响历史 |

## 8. 隐私红线（在任何阶段都不能越）

- ❌ 不在服务器端保留任何能解密的密钥。
- ❌ 不把"便利"放在"加密"之前（例如为了搜索而在服务端建明文索引）。
- ❌ 不静默开启公开发布——每次分享必须显式勾选并展示"将公开哪些记忆"。
- ❌ 不信任任何第三方"托管密钥"方案。
