> **文档定位**：战略级设计原则 + 重建路线。供老板拍板范围、技术团队落地参考。
> **重要**：本文档**不动任何代码**，是"想"阶段的产物（对应思路过程的第 0+2 步）。
> **生成方**：QwenPaw 内置 QA Agent，基于 Lumina 现有代码与多份修复报告的诊断。

## 0. 前提：故障终审（B 成不成的总开关）

把"途中一直优化修复总是出问题"的故障做归类：

- **功能 / 技术债类**（补丁没打全、模块打架）
  例：头像 emoji 不显示、Windows 通知不弹窗、默认界面、魔搭社区爬取失效等（见 `LUMINA_DIAGNOSIS_AND_FIX_REPORT.md`）。
  → 这类 B 能消债（干净起点洗掉旧债）。

- **根因误诊类**（反复试错、没打在根上）
  例：团队后台 agent（写代码 / 审查）"不会"、答非所问。真因是——**后台干活的员工脑子里是空的，只在被派活时临时塞一张工作纸条**（见 `LUMINA_ORIGIN_FIXES.md`；代码侧表现为群聊场景 prompt 退化为三句话、技能仅委派时临时注入）。
  → 这类 B **解决不了**，除非把根因写进新设计。

**终审结论**：故障是混合的，但"群聊 agent 这一块"偏根因误诊。
⇒ **B 要想不变成"用更大代价重演同样故事"，必须把"员工自己带脑子"作为新底层的设计宪法（见第 2 步）。**

## 2. 三条设计原则（新底层的"宪法"）

借鉴 QwenPaw 好用的地方，翻译成 Lumina 的新规矩：

1. **员工自带脑子**
   每个干活的 agent 运行时**始终带着自己的技能手册（常驻）**，不是总管临时喂。
   → 直接治"根因误诊"那个病根。

2. **标准工单通信**
   agent 之间用**统一工单接口**协作，各干各的、互不污染上下文。

3. **技能是固有能力**
   技能从**统一中心**加载、作为 agent 自身能力，不是散落各处的文档。

---

## 3. 新底层蓝图（部门图）

重组为职责单一、不互相踩脚的部门：

```
┌─ Lumina 新底层 ───────────────────────────┐
│  Agent 工作间   （每个员工独立，自带技能）   │
│  技能中心       （统一发手册、常驻注入）     │
│  委派总线       （员工间传工单）            │
│  记忆中心       （长期/短期/共享上下文）     │
│  对外接口层     （将来接多端，先留空）       │
└──────────────────────────────────────────┘
```

目标只有一个：**不再出现"补丁叠补丁、模块打架"**。

## 4. 迁移节奏（分批搬家，不一夜推平）

- 先搭新地基（技能中心 + Agent 工作间骨架）
- **第一批搬：群聊 agent**（最痛，先验证新地基对不对）
- 搬完一个验收一个，每批都有"能跑的 checkpoint"
- 中途不全盘瘫痪

---

## 5. 验收标准（动工前写死）

- 群聊 3 agent 不再说"我不会 / 无法"
- 加新功能不再引发旧毛病
- 稳定性（崩溃率）、技能命中率达标
