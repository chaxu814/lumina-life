## 一、战略定位重申

**Lumina 要服务谁？**
普通用户、低端市场用户。他们不懂 LLM、不会配 API、不想看报错，只想“下载安装→能用→好用”。

**核心竞争力：**
1. 有情感的 AI 陪伴（Lumina 猫娘人格）
2. 有团队的多 Agent 协作（Lumina + 热茶 + Yak）
3. 能主动的桌面助手（主动引擎、Computer Use）

**当前最大瓶颈：**
- 团队 Agent 工具调用失败（搜不出东西、无限循环）
- 基础体验 bug（通知、emoji、默认界面）
- 配置门槛高
- 技能市场半不可用

## 三、本次动手优先级（先攻最痛的问题）

### 当前最高优先级：团队 Agent 搜索失败

**现象（已截图确认）：**
- 用户说“搜索最近 A 股问题并总结”
- 热茶说“让我使用搜索引擎”，随后陷入多轮“思考中… 空回复… 自动继续”
- Lumina 输出 raw `<tool_call>` XML，工具未真正执行

**根因：**
1. 群聊场景的 `agentChat` 调用没有强制走 function calling。
2. 模型输出 `<tool_call>` XML 后，系统没解析执行，而是把 XML 当普通文本显示。
3. 工具失败后没有停止机制，导致无限重试。

**修复动作：**
1. 在 `GroupChatView.tsx` 的 `agentChat` 调用中，明确启用 `mode: 'agent'` 并带上完整工具集。
2. 在 `agentRunner.ts` 的 ReAct 循环中，增加对 `<tool_call>` XML 的解析兜底。
3. 给团队 Agent 加“必须执行、禁止只说不做”的 prompt 铁则。
4. 加工具调用失败计数器，失败 2 次后停止并返回错误。

## 四、代码改动原则

1. **先备份**：每个核心文件改动前生成 `.bak.QwenPaw.YYYYMMDD` 备份。
2. **小步快跑**：每个改动一个独立提交/保存点，方便回滚。
3. **不删旧接口**：新逻辑兼容旧逻辑，避免现有功能崩溃。
4. **可观测**：每次关键调用加日志，方便调试。

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 改动太多导致其他功能崩 | 小步快跑 + 备份 + 每改完一个模块验证 |

| 低端机器跑不动 | 提供性能分级，默认轻量模式 |
| 多 Agent 协作仍不稳定 | 先保证单 Agent 任务稳定，再优化协作 |
