「5 个 agent」的真相（先纠正这个直觉）

cc-haha 没有固定的 5 个 agent。你看到的 5 人是文档里的一张示例团队拓扑图。它的团队是三层概念：

  • 6 种内置工种（Claude Code 自带）：general-purpose（全能）、Explore（只读快搜，跑 Haiku 小模型）、Plan（只规划不写文件）、verification（常驻后台，输出 PASS/FAIL 判定）、claude-code-guide（文档查询，Haiku）、statusline-setup（状态栏配置，范围极小）。
  • Agent Teams：Lead 运行时 TeamCreate 建队，按需 spawn 任意数量成员，给名字、选工种、选模型、选工具池、选权限模式，干完发 shutdown_request 握手解散。
  • 工作台 8 种职业头像：team-lead / server-engineer / ui-designer / qa-engineer / security-reviewer / data-analyst / release-engineer / docs-coordinator——纯视觉角色，按成员名字和任务关键词正则匹配。

所以正确的对比不是「3 个 vs 5 个」，而是「3 个固定人格」 vs 「1 个 Lead + 任意数量临时工种」；你也不是严格 3 个——你的实习生池就是同一思路的雏形，只是被限定在代码场景。

04cc-haha 团队的 8 个新奇点（按可借鉴度排序）

1文件信箱 + 共享任务板（最值得抄）

成员不互相等：inboxes/{name}.json 1 秒轮询、文件锁防并发；任务板上每人自己 claim 任务、更新 owner、查 blockedBy。Lead 不用逐个人派活，团队像真的敏捷小组一样自组织。

你的 taskBoard.ts 已经有 DAG/并行组/owner 字段，差的是「worker 自己 claim + 信箱轮询」这一层。

2模型当场写的 Workflow 脚本

不是预设套餐，而是模型在对话里现写一段 JS：parallel() 屏障、pipeline() 无屏障流水（A 件到第 3 阶段时 B 件还在第 1 阶段）、schema 强制结构化输出、token 预算硬上限、并发帽、journal 断点续跑（改一处只重跑变更点，前面全缓存）。

你的 workflowTemplateManager.ts 是「预设 prompt+工具套餐」，phaseGate 是写死的代码，两者都不是运行时脚本。

3对抗式验证模式库

每个发现派 N 个独立「怀疑者」专门去反驳，多数票反驳成功就杀掉；多视角评审（正确性/安全/性能/可复现）；评审团出 N 个独立方案再打分嫁接；loop-until-dry 连续 K 轮没新东西才停；最后一个「完整性批评员」专问漏了什么。

热茶现在被 prompt 限定「只报 1 个最严重问题」，可以升级成多视角投票。

4git worktree 隔离并行

多个 agent 同时改文件，各自在独立 worktree/分支里跑，互不踩；无改动自动清理；非 git 仓库降级为普通目录。配合分支/Worktree 启动会话和整轮 Diff 可撤销。

你有 gitAgent.ts 和实习生并行，但并行写没有隔离层——这是实习生一多就会踩的坑。

5Agent 即 Markdown，热加载

自定义 agent 就是一个带 frontmatter 的 .md（tools/model/effort/permissionMode/maxTurns/skills/memory/isolation…），用户级/项目级两个目录，保存即热重载，同名按 6 级优先级覆盖。

你路线图 v1.1 要做自定义 Agent，这是现成答案；甚至比你现在的 agent.json 更适合让用户手写。

6可视化工作台（泳道+站位+通信流）

任务按依赖深度自动分列（拓扑最长路径算泳道），成员头像实时站在自己当前任务上，消息流、plan 审批、关停握手全可见，还能回放历史快照（被解散的成员仍保留其任务和对话）。

这是把「多 agent 在干嘛」从黑盒变成直播，天然适合你的团队社交叙事。

7关停握手与 idle 语义

队员每轮干完自动 idle（不是退出，发消息即可唤醒）；任务结束 Lead 发 shutdown_request，队员 approve 后才解散；prompt 反复教模型「别看到 idle 就以为人家挂了」。

你的实习生是 dismiss 即销号，缺少「挂起待命」和优雅收尾。

8小模型干杂活的成本意识

Explore / claude-code-guide 这类只读工种默认跑 Haiku 小模型，强模型只给 Plan 和实现；自动后台化、token 用量统计、Workflow 必须用户显式 opt-in（说 ultracode 才大规模扇出）。

你全团同一个 9B 时没差，一旦接强模型 API，这就是真金白银的成本控制。

但有 4 件事，它抄不走你

① 连续自我：它的 agent 是一次性工牌，无名字延续、无独立记忆；你的三人有独立记忆（agentIndependentMemory.ts）、关系、情绪历史。
② 社交生活：群聊、朋友圈、早安仪式、亲密度随真实委托演化——它的「团队」只在任务期间存在，你的团队 24 小时在你电脑里过日子。
③ 情绪进入调度回路：心情影响派单路径和主动性，这是「生命体」才有的架构。
④ 小模型友好的工程哲学：SoM 网格、阶段门、规则复杂度分析是为「没 Claude 也能跑」设计的；cc-haha 的下限绑定 Claude 级模型。
