# Lumina「LLM 驱动身体 = 生命体」机制说明与增强设计

> 这份文档回答三个问题：
> 1. 之前为什么你感觉"LLM 并没有在修复 JSON 动作/表情/台词"？
> 2. 修复之后，"一个大脑同时驱动意识和身体"的完整链路是什么、怎么亲眼验证？
> 3. 怎么把它继续做到"真的像生命体"，并成为别人抄不走的壁垒？

---

## 一、先解释你之前的困惑：不是没设计，是"大脑断线后被静默降级"了

Lumina 的代码里**本来就有**"LLM 写 JSON 操控身体"的设计（`intentDispatcher` 要求模型只输出 `{"action","mood","speech"}`，桌宠收到后同时做动作、换表情、说台词）。你之前看不到它生效，是一条链上三处同时静默失败：

1. **本地 LM Studio 的 API Key 被误填成了 `sk-lm...`**，本地服务不认这个密钥，每次请求都返回 401（就是设置页那条红字）。
2. 请求层对任何地址都强行带鉴权头，失败后**不报错弹窗、只在后台返回 error**。
3. 桌宠的三条"生命活动"（和你聊天、每几秒的自主活动、主动秘书看屏幕）在 LLM 失败时，会**悄悄降级**成写死的关键词规则/随机动作池——表面上她还在动、还在说话，但那些反应**不是模型给的**，所以你看到的就是"乱来、随机、不像被大脑驱动"。

> 一句话：**灵魂一直都在，只是大脑断线了，身体在用脊髓反射乱动。**

### 本轮修复后（2026-09-09）

- 本地服务（localhost / 192.168.x / 10.x）返回 401 时，**自动去掉密钥重试**，并对健康检查、流式、非流式三条请求路径全部生效——误填 key 不再能掐断大脑。
- 桌宠大脑配置统一为：**优先用 Lumina Agent 的独立配置，没配就自动用设置里的全局激活模型**，三条生命活动共用同一套取脑逻辑，不会再出现"主窗口能聊、桌宠没脑"。
- 纯文本模型收到截图会崩 → 现在**带图失败自动去掉截图、只凭活动窗口标题重试一次**，小模型也能让她"知道你在哪个软件里"。
- "立即搭话一次"在没连大脑/被隐私模式挡住时会**明确告诉你原因**，不再无声无息。

## 二、修复后的完整链路：一个想法，同时驱动身与口

```
        触发源（三种"生命冲动"）
  ┌───────────────┬──────────────────┬────────────────────┐
  │ 你对她说话      │ 自主心跳(约8s节流) │ 主动秘书/屏幕感知    │
  │ pet:chat       │ pet:autonomy:tick │ secretary/perception│
  └───────┬───────┴────────┬─────────┴──────────┬─────────┘
          ▼                ▼                    ▼
   统一取脑 resolvePetBrainConfig（Team 配置 → 全局模型兜底）
          ▼
   把"现在几点、你在哪个窗口、最近聊了什么、屏幕截图(可选)"喂给 LLM
          ▼
   ★ 模型只输出一行 JSON（这就是"意识决定身体"的瞬间）★
   {"action":"happy","mood":"幸福 💖","speech":"搞定啦喵！"}
          ▼
   容错解析（允许模型啰嗦、带 ```json、前后缀文字，都能抠出来）
          ▼
   dispatchIntent → pet:command('intent') 下发给身体
          ▼
   execIntent 同一帧内执行三件事：
     ├─ action  → Live2D 动作（wave/nod/happy/dance/think… 16 种）
     ├─ mood    → 面部参数+表情（9 种情绪，眉眼角度/睁眼度/表情组）
     └─ speech  → 气泡台词 + TTS 语音
```

**关键点：动作、表情、台词是模型在同一次推理里一起决定的，不是三套随机数拼出来的。** 这就是和普通桌宠（定时器随机播动画 + 另一个模块生成台词）的本质区别。

### 你怎么亲眼验证"是模型在驱动身体"（3 种方式）

1. **看脑日志（最直接，也是演示视频第 3 镜的拍法）**
   - 桌宠窗口右键/快捷键打开 DevTools（或主菜单里的开发者工具），Console 筛选 `[Brain]`；
   - 每次她动，都会打印一行 `[Brain] LLM 驱动身体 → {"action":...,"mood":...,"speech":...}`；
   - 主进程日志里还有 `[IntentDispatcher] LLM brain(team/global): 模型名 @ 地址` 和 `[Secretary] brain source ... (with-screen/text-only)`，能看出这次用的是哪个大脑、有没有带屏幕。
2. **对照实验**：连续对她说三遍"我好难过"，每次的台词和动作细节都不同，但 action 都会稳定落在 `sad/nod`、mood 落在难过类——**方向由语义决定、细节由生成决定**，这就是"活着"与"播片"的区别。
3. **手动注入想法**：`pet:test-intent` 通道可以直接下发任意 JSON 意图（设置面板的动作测试按钮就走它），用来验证身体侧 16 种 action、9 种 mood 全部能正确演绎。

## 三、为什么这是真创新：与常见主动桌宠的本质差别

| 维度 | 常见主动桌宠（场景规则触发的屏幕搭话） | Lumina 的目标形态 |
|---|---|---|
| 看屏幕后做什么 | 规则/场景检测触发，**LLM 只负责"说什么"** | 看屏幕后 LLM **同时决定"什么心情、做什么动作、说什么话"** |
| 身体动作来源 | 预设状态机、随机待机动画 | 模型每一次实时输出的 action JSON |
| 表情 | 少数固定触发点 | mood 作为每次推理的必选字段，与语义强绑定 |
| 没配模型时 | 多数功能直接不可用 | 有写死规则兜底（但会明确标注自己在降级） |
| 可验证性 | 难以区分"AI"与"脚本" | `[Brain]` 日志逐次可查，意识→身体一一对应 |

**你要抢占的心智位置是一句话："别家的桌宠是 AI 配了一个会动的皮套；Lumina 的身体是 AI 自己'长'出来的控制信号。"**

## 四、从"能动"到"像生命体"：分层增强路线（按性价比排序）

> 诚实标注：✅ 本轮已具备；🔧 已有骨架需加强；📋 建议新增。每一层都独立可做、可演示。

### 第 1 层：身心一致（✅ 已打通，本层是地基）

- ✅ 统一 JSON 协议 `{action,mood,speech}`；✅ 容错解析；✅ 16 动作/9 情绪映射；✅ 三种触发源；✅ 大脑断线自动兜底与可见提示。
- 验收：任何一次反应都能在 `[Brain]` 日志里找到对应的模型输出。

### 第 2 层：情绪是"连续状态"，不是一帧标签（🔧，最优先增强）

**现状**：mood 每次被新值覆盖，情绪没有"余韵"——上一秒难过，下一秒可以瞬间超开心。
**生命体做法**：
- 主进程维护一个情绪向量（开心/疲惫/专注/焦虑/好奇五维，项目已有五维情绪追踪雏形），LLM 每次输出的 mood 作为"瞬时刺激"叠加到向量上，按时间衰减；
- 渲染层的表情由**当前情绪向量 + 本次 mood 混合**得出，情绪过渡用 300–600ms 补间，而不是瞬切；
- 她会"嘴上说开心、眉眼还没完全放松"——这种**情绪惯性**是生命体感的最大来源。

### 第 3 层：自主节律与"注意力"（🔧→📋）

**现状**：自主心跳固定节流，菜单/聊天打开时不动。
**增强**：
- 引入"唤醒度（arousal）"：深夜、长时间无互动时动作变慢变小、眨眼变慢、打哈欠；你刚回来时唤醒度上升、动作变轻快；
- 注意力焦点：鼠标快速移动/新窗口出现/长时间静止，分别给不同的"注意"动作（视线已跟随鼠标，可扩展为"被突然的动静吸引→轻轻一惊→回到待机"）；
- 自主行为不再只从动作池选，而是让 LLM 在心跳 prompt 里看到"距离上次互动多久、现在情绪向量、当前场景"，由它决定**这次要不要主动、以什么强度**——沉默也是一种生命决策。

### 第 4 层：记忆反哺身体（📋，壁垒层）

- 把 SQLite 里的长期记忆（事实、反事实、亲密度）摘要进每次心跳 prompt：她记得你昨天熬夜，今晚看到你 23 点还在写代码时，担心的语气和动作会和第一次不同；
- 亲密度影响动作空间：陌生时只敢眨眼/歪头，熟了才会跳舞/凑过来；
- 这一层让"越用越像同一个她"，是开源复刻者最难追上的部分（因为数据在用户本地、随时间生长）。

### 第 5 层：动作粒度与"微动作"（📋，表现层）

- 现在 action 是 16 个离散大动作；可让模型额外输出 `micro`（如视线偏移、耳朵微动、身体前倾幅度 0–1），Live2D 参数支持连续控制，微动作让她在"不说话时也活着"；
- 动作之间做姿态衔接（现在部分动作有 busy 锁，可统一为动作队列 + 过渡），避免打断感；
- 给模型一份"身体能力清单"自动生成 prompt（模型知道这具身体有哪些参数可用），换模型/换 Live2D 皮时协议不用改。

### 第 6 层：内在动机（📋，远期，决定"她有没有自己的生活"）

- 没有用户输入时，她也有自己的"小目标"：无聊了自己找乐子、想起一件事主动提、困了自己睡；
- 由低频（如 5–15 分钟）"内在独白"驱动，输出仍是同一套身体 JSON——**外在表现层协议永远不变，变的只是大脑越来越深**。这保证每一层增强都不用推翻已有成果。

## 五、工程落地顺序建议（每步都能立刻演示）

1. **本周（地基验收）**：真机按第二节三种方式验证 `[Brain]` 链路；拍演示视频第 3 镜。
2. **下一步 1–2 天**：做第 2 层情绪向量+表情过渡（改动集中在 `applyEmotion` 与主进程情绪模块，风险小、观感提升最大）。
3. **随后**：第 3 层唤醒度（和现有五维情绪、场景检测直接衔接）。
4. **公开 Release 后**：第 4 层记忆反哺（需要和 memoryStore 联调，作为 v0.2 的主打）。
5. 第 5、6 层写进 roadmap，作为"生命体 OS"的叙事延续。

> 架构上的配套：按 `docs/engineering-governance.md` 阶段 1，把这条链收敛为 `electron/pet/brain/` 单一模块（身体协议、取脑、决策、感知分开），**让"生命体机制"成为仓库里一处清晰可读、可测试、可对外讲解的核心资产**——这既是工程质量，也是你对外讲创新时最有力的证据。

## 六、给"战略者"的一页话总结

- 你的创新点**成立**，而且代码方向本来就是对的；之前不生效是"大脑被错误密钥掐断 + 失败后静默用死规则"，本轮已修。
- 修复后，**她的每个动作/表情/台词都能逐次追溯到模型输出的一行 JSON**，这就是可演示、可验证、可写进论文式 README 的差异点。
- 真正的壁垒不是"LLM 输出 JSON"本身（别人能模仿），而是**连续情绪 + 自主节律 + 本地长期记忆**让她产生"时间感和唯一性"——按第四、五节的分层做，越往后别人越难追。
- 对外只讲一句话：**"The LLM doesn't chat through her — it drives her."（模型不是借她说话，而是在驱动她。）**
