二、项目是什么（一句话与三条产品线）

Lumina Life 卖的是三个东西的交集：

  1. 有形象的桌宠：Live2D（主线）/ VRM（beta）/ 8×9 精灵表 UGC / MMD / 程序化猫咪，五种形态；

  3. 三 Agent 团队：Lumina（唯一对用户入口、情绪与陪伴）+ Yak（代码工程师，工具白名单）+ 热茶（只读审查员，工具黑名单），含五阶段门控、对抗评审、动态雇工、团队社交。

它想填的空位是："有形象的 AI 伴侣大多没有干活的 Agent 能力，有 Agent 能力的工具大多没有人格。"这个判断经赛道调研证实基本成立（匿名量级事实见第六章）。

4.2 主张二："情绪进执行层，只收紧不放宽"——✅ 真创新，已接线，成色最足

  • 逻辑（orchestration/emotionGating.ts）：焦虑 ≥0.35 且效价 ≤−0.1 → 暂缓不可逆工具（删文件/发邮件/git push/桌面操控）；疲劳 ≥0.6 → 暂缓重负载工具；实现里只有 suppress 集合、没有任何放开分支，代码注释明确写"防止后来者顺手加放开分支"（因为"让模型开心就解锁权限"本身就是社工攻击面）。
  • 接线：在 rolePolicy 角色过滤之后执行（情绪永远叠在角色边界之内、不可能突破角色权限）；有 features.emotionGating 开关（默认开）；有因果链（Yak 连续失败→焦虑升高→收紧，逐维取 min 保证只更严）；每次收紧写审计日志（emotionAudit.ts），用户可"本轮放行"。
  • 赛道调研覆盖的同类项目（陪伴型桌宠、多 Agent 桌面工作台、agent 状态显示器三类）中，情绪数值真实参与工具可用性决策的，未发现第二家；同类产品的情绪/状态全部停留在表现层（换表情、换台词）。

保留意见：底层三维情绪（mood/energy/affinity）的漂移公式仍是玩具级（只有昼夜两档、未做连续正弦），且没有对照实验、没有留存数据。机制创新成立，"她真的有情绪"的体感价值未被验证。把审计变成用户可见的"为什么拦我"面板是创新想法 #1。

4.3 主张三："常驻架构是没法被加功能补上的优势"——✅ 架构红利真实，但不是护城河

  • 真实部分：桌宠形态天然常驻，proactiveEngine（7 类触发、dHash 帧差节流、夜间勿扰、maxDaily=80、120s 最小间隔）、IM 适配、H5 远程批准（/m，局域网）都是"常驻之后才有意义"的能力。

十一、创新想法清单（9 个，按"价值/做法/工作量"给出）
