二、项目是什么（一句话与三条产品线）

Lumina Life 卖的是三个东西的交集：

  1. 有形象的桌宠：Live2D（主线）/ VRM（beta）/ 8×9 精灵表 UGC / MMD / 程序化猫咪，五种形态；本轮新增第七种状态 frugal「精打细算」（预算守护者触发）；
  2. 真能干活的桌面 Agent：Computer Use（截图→VLM→键鼠注入）、139 个注册工具（chat 档 11 个、agent 档常驻核心约 32 个 + 按需命中、developer 档 139 个；/decide 是确定性命令不计入）、CLI、REST API、MCP、LSP、自定义 Agent；
  3. 三 Agent 团队：Lumina（唯一对用户入口、情绪与陪伴）+ Yak（代码工程师，工具白名单）+ 热茶（只读审查员，工具黑名单），含五阶段门控、对抗评审、动态雇工、团队社交；本轮新增决策三栏（执行者 pros/cons + 审查员风险反对 + Lumina 综合）与交班模式（把团队状态交给下一个会话/另一台机器）。

它想填的空位是："有形象的 AI 伴侣大多没有干活的 Agent 能力，有 Agent 能力的工具大多没有人格。"这个判断经赛道调研证实基本成立（匿名量级事实见第六章）。

4.6 本轮新增的六个实验功能（全部落地、接线、有测试、进包）

统一入口：设置面板「实验功能」tab。预算守护者常驻默认开，其余 5 个默认关——默认关即"与复评版行为等价"，有 labFlagsWiring 测试与干净克隆实证兜底。

4.6.1 预算守护者（electron/billing/：priceTable.ts / usageLedger.ts / budgetGuardian.ts / billingIpc.ts）

  • 机制：LLM 调用层统一记账，在 llmProvider + agentRunner 两个出口收口；有真实 usage 记真实 usage，缺 usage 时估算并显式标 estimated；单价表可配置（DeepSeek / 硅基 / 通义 / OpenAI）。每日预算支持 ¥/天档位 + 自定义 token 上限。
  • 三级只收紧（与情绪门控同一哲学，无任何放宽分支）：80% 提醒 + 桌宠第七态 frugal；95% 降级便宜模型并暂停社交/主动等非必要调用；100% 仅保留用户主动对话。0 点自动重置。
  • 诚实/安全设计：审计因果链可查、预算面板可见、estimated 估算不冒充真实用量。
  • 测试：计入 billing 三件套合计 50 用例；开关：实验功能 tab（默认开）。

4.6.2 Day Replay（electron/dayreplay/）

  • 机制：把账本 / 命令审计 / 任务看板 / 雇工池聚合为每日时间线，面板查看 + 导出 Markdown / 纯文本；按本地时区跨天。
  • 诚实设计：明确标注数据源覆盖——命令审计/看板仅内存进程态、filesChanged 为 best-effort、空日不编造内容。这是"宁可说没有，也不凑时间线"的做法。
  • 测试：19 用例；开关：实验功能 tab（默认关）。

4.6.3 Mood×Productivity（electron/moodstats/）

  • 机制：工具执行与委托快照记录 mood / energy / affinity + 结果，SQLite 落盘（不可用时降级内存 / JSONL，不崩）；五档 × 三档分桶 + 趋势 + CSV / JSON 导出。
  • 诚实/安全设计：A/B 对照默认关——对照组关情绪门控但照常记录，UI 明示分组、分组稳定、可退出；每桶样本 <30 时显式输出"数据不足，不构成结论"，不拿小样本编相关性。
  • 测试：18 用例；开关：实验功能 tab（默认关）。

4.6.4 仪式感闭环（electron/rituals/）

  • 机制：睡前复盘默认 23:00（消费 Day Replay → LLM 口播 → TTS + 桌宠动作）；晨间简报默认 8:00（天气 / 日历 / 待办 / 未完成项，逐项降级，城市默认河池）。
  • 诚实/安全设计：TTS 失败降级文字气泡；无 LLM 走模板并标注来源 llm / template；预算超限自动暂停仪式；时间修改热生效。
  • 测试：20 用例；开关：实验功能 tab（默认关）。

4.6.5 决策三栏（electron/decision/）

  • 机制：显式 /decide 或句首"帮我决定…"才触发，不自动路由；执行者视角 pros/cons + 审查员视角风险反对 + Lumina 综合（并发 + 超时降级 + 完整性兜底 + 模板兜底）；ChatPanel 三栏卡片呈现。
  • 安全设计：Lumina 唯一入口，后台成员不外露（角色铁则不破）；超时与模板兜底保证永远有结果而不是转圈。
  • 测试：13 用例；开关：实验功能 tab（默认关）。

4.6.6 交班模式（electron/handover/）

  • 机制：交班卡片（Day Replay 摘要 + 待审批 + 待办 + 三 Agent 状态 + TTL）；口令经 scrypt / pbkdf2 派生 + AES-256-GCM，或走本机密钥（safeStorage / DPAPI），导出 .lumina-handover 文件；二维码只放局域网 URL（24 字符随机交换码、内存 TTL）；/m/handover 页面端 WebCrypto 解密——口令与明文不过服务器；审批复用既有 /api/approvals 端点；过期卡锁定。
  • 安全设计：明示仅局域网；端解密把"过服务器"这条路从协议上堵死；TTL 过期即锁。
  • 测试：25 用例；开关：实验功能 tab（默认关）。
