四、核心主张的机制核验（真创新 / 半实现 / 包装词）

4.1 主张一："桌宠绑定真实 Agent 执行状态"——⚠️ 真机制，覆盖率约一半（本次审计最重要的发现）

真实的部分：electron/pet/agentStateBridge.ts 把 taskBoard + internPool 的真实任务映射为 idle/working/reviewing/waiting/attention/celebrating 六态；intentDispatcher.ts:99-124 每 3 秒轮询下发；零 LLM 调用（纯状态机，不花 token）、1.2s 防抖、空闲不接管、可 LUMINA_PET_AGENT_STATE=0 关闭。对比 cc-haha 作者自述"桌宠只是状态提示和跳转入口，不能替你批准权限"、AIRI 表情来自模型随机输出——Lumina 确实越过了这条线，且方向正确。

缺口：状态桥的两个数据源里，taskBoard 只在 delegationManager.ts:1229 的复杂任务分支（phaseGate 五阶段）创建；简单委托在第 1217–1224 行直接 return this.delegate(...) 直派 Yak，不看板；internPool 只服务并行雇工（yakParallel）。而用户最高频的"帮我修个 bug / 写个函数"恰恰走简单委托。

结论： - 这不是假功能（复杂任务、并行雇工时桌宠真的会敲键盘/做审视态，且 H5 远程批准也是真实的），但 README 第 255 行"Yak 正在写代码 → 敲键盘循环"在最常见场景下不会发生。 - README 第 791 行把它列为"已完成"，docs/ROADMAP.md 却把它放在 v0.3.0 未勾选——发布前必须二者择一：要么把普通 delegate_to 也写进看板（工程量不大，在 delegationManager 简单分支补 register/finish 两个事件即可），要么在 README 降级为"复杂任务时"。

4.2 主张二："情绪进执行层，只收紧不放宽"——✅ 真创新，已接线，成色最足

  • 逻辑（orchestration/emotionGating.ts）：焦虑 ≥0.35 且效价 ≤−0.1 → 暂缓不可逆工具（删文件/发邮件/git push/桌面操控）；疲劳 ≥0.6 → 暂缓重负载工具；实现里只有 suppress 集合、没有任何放开分支，代码注释明确写"防止后来者顺手加放开分支"（因为"让模型开心就解锁权限"本身就是社工攻击面）。
  • 接线（agentRunner.ts:4074-4139）：在 rolePolicy 角色过滤之后执行（情绪永远叠在角色边界之内、不可能突破角色权限）；有 features.emotionGating 开关（默认开）；有因果链（Yak 连续失败→焦虑升高→收紧，逐维取 min 保证只更严）；每次收紧写审计日志（emotionAudit.ts），用户可"本轮放行"。
  • 对比：AIRI、NEKO、clawd-on-desk 的情绪/状态全部停留在表现层（换表情、换台词）。"情绪数值真实参与工具可用性决策"在调研覆盖的同类项目中未发现第二家，且安全方向的设计约束（单向收紧）显示出超出一般个人项目的安全直觉。

保留意见：底层三维情绪（mood/energy/affinity）的漂移公式仍是玩具级（README 自承"只有昼夜两档、未做连续正弦"），且作者自承没有对照实验、没有留存数据。机制创新成立，"她真的有情绪"的体感价值未被验证。

4.3 主张三："常驻架构是没法被加功能补上的优势"——✅ 架构红利真实，但不是护城河

  • 真实部分：桌宠形态天然常驻，proactiveEngine（7 类触发、dHash 帧差节流、夜间勿扰、maxDaily=80、120s 最小间隔）、IM 适配、H5 远程批准（/m，局域网）都是"常驻之后才有意义"的能力；MiniMax Code 的定时任务也依赖桌面端常驻。
  • 但说"没法被后来者补上"过了：cc-haha 本身就是常驻 Electron 多 Agent 桌面端，openclaw 系也有常驻方案；架构红利让 Lumina 做这些功能更顺手，并不构成壁垒。真正的壁垒候选是"常驻 + 情绪执行层 + 可见状态"三者的组合体验，而不是常驻本身。

  • 职责区分度高，措辞区分度弱：SOUL_YAK（104 行，9 条干活铁则）与 SOUL_RECHA（109 行，8 条审查铁则）把"做什么"分得很清，但"怎么说话"几乎没写——热茶的"毒舌"主要活在 README 文案里，实际指令是"不寒暄、先给结论"，Yak 也是"不寒暄、不角色扮演"，两者输出风格会趋同为干巴巴的结论清单。"亲密度高→先肯定再建议"有数值驱动的提示词注入，但温差预计很小。
  • 温度配置（0.7/0.3/0.2）与角色匹配，合理。
  • 协作工程质量是全项目最硬的部分之一：深度闸、收敛检测、缓存、上下文隔离、五阶段降级（复杂任务自动降级为简单派活，防止过度编排）、/yak /recha /lumina 确定性命令给专业用户兜底——这套"灵活性 + 逃生门"的取舍是成熟设计。

7.4 记忆

  • 落 SQLite（WAL，%APPDATA%/lumina-memory.db），每 Agent 独立 fact/social/persona 空间 + 团队共享层；可导出开放格式（manifest + memory.md + 每表 JSON），导入按主键去重不覆盖。

九、使用模拟（无真人数据，推演）

9.1 普通用户（非技术、想要陪伴/省事）

  • 现实路径：本次发布没有现成安装包 → 普通用户连入口都没有。假设有 NSIS 包：首启动向导默认推 DeepSeek 云端（onboarding 默认 deepseek），需要用户自己注册 DeepSeek 并充值拿 key；不填 key 则桌宠会动、有模板台词，但聊不了天——这是第一流失点。README"开箱已预填三家云端 Provider"的说法与发货模板（agents/*/agent.json 全是 lmstudio/your-model-name 占位、.env.example 默认 lmstudio）不符，预填只在向导运行时发生。

9.2 专业用户（程序员/想跑真任务）

  • 完整度：shell/文件/git/LSP 工具链、CLI、REST API（10+ 端点）、MCP server、自定义 Agent（leader/member/solo 三级）、技能 SDK——扩展点齐全且都是真的。

9.3 总评
