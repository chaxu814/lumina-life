`const ts = TOOLSETS[name]` —— **只读静态常量表，完全不读 `ToolDef.toolsets`**。
而 `TOOLSETS.team`（`:93-97`）只列了 10 个。

**结果：47/132 个已注册工具在任何模式下都够不到**：

## 2.2 逐项修复说明

### ① 工具可达性 —— 分层设计，不是无脑合并

**不能全并的原因**（实测）：`toolsets:['agent']` 被宽泛标注了 **121/132** 次
（邮件、创作者、浏览器、搜索全写着 agent）。直接合并会让 agent 模式从 34 涨到 121，
三档按需加载的分层设计当场作废（每轮多塞 87 个 schema，烧 token 还稀释选择）。

**采用的方案**：
- **模式层**（`chat`/`agent`/`developer`）由 `MODE_TOOLSETS` 标记，静态表独占
- **能力层**（`team`/`lsp`/`browser`/`computer_use`/`creator`/`research`/
  `media`/`social`/`voice`/`news`）改为声明式自动解析
- 新增 `full` = 全部已注册工具
- 补齐 10 个**此前在静态表里根本不存在**的能力层占位 —— 修复前
  `developer` 的 `includes` 引用 `lsp`/`code`/`browser` 时静默返回空集，
  整层代码工具永远拿不到且无任何报错
- 未定义的 toolset 名现在告警而非静默返回空
- 启动日志打印各档可达数 + 对孤儿工具告警

> **真机复评补充（2026-10-04）**：孤儿守卫修好之后立刻报出**8 个真实孤儿**
> （`developer_companion_check` / `process_list` / `memory_chat_search` /
> `time_capsule` / 4 个搜索引擎）。根因是它们只声明了模式层 `agent`/`developer`，
> 而模式层按设计由静态表独占，声明不进去。已为它们补 `dev_tools` 与
> `search_engines` 两个能力层 —— 最终 `agent=56 / developer=82 / 孤儿=0`。

### ② 断环修复

`agentRunner.ts` 在模块顶层调 `registerAllTools()`，依赖链是环的：
```
tools/index.ts → impl/* → asyncTaskManager.ts → agentRunner.ts:111
                → registerAllTools() → 读 tools/index.ts 的模块级绑定（TDZ）
```
改法：调用点移入 `AgentRunner` 构造函数（此时依赖图已 100% 求值），
标志位移入零依赖叶子模块 `tools/registrationFlag.ts`（CAS 语义防重复注册）。

**副作用**：`longConversation.test.ts` 那个红灯随之消失。

### ③ 五阶段门控接线
新增 `tools/impl/phaseGateDelegate.ts`，挂出 `phase_gate_delegate` 工具。
它内部已实现的「简单任务自动降级为 delegate_to」分支正好省掉在 prompt 里教一遍。

### ④ 证据链接线
新增 `memory/evidenceBridge.ts` 作为**适配层**而非改写任一套：

| 机制 | 作用 | 状态 |
|---|---|---|
| `SOURCE_CONFIDENCE`（`memoryStore.ts:55`）| 写入期硬约束 —— 权威性**只由 `source` 决定** | 一直在线，未改动 |
| 五维证据评分（`memoryEvidence.ts`）| 读取期排序与生命周期 | v3.34 接通 |

不变式：不引入第二个「谁说了算」。`memoryEvidence` 新增 `findByContent` /
`contradictByContent` 公开入口（不改原私有方法可见性）。

### ⑤ 测试与门禁

- `vitest.config.ts` 的 `include` 纳入 `electron/**/__tests__/**`（此前 7 个文件永不执行）
- 修好 3 处陈旧断言 + `require('electron')` 导致 shell 测试不可测的问题
- 3 个「读源码文本」断言改为对花括号/空白不敏感（`eslint --fix` 补花括号会打红它们）
- CI：`tsc --strict` 移除 `continue-on-error`；ESLint error 门禁 + **warning 棘轮制**
  （`scripts/lint-ratchet.cjs` + `lint-baseline.json`，只允许变小而非假装清零）

### ⑥ 顺带修的真 bug

`electron/gaming/botRoute.ts`：
```ts
- const slot = Math.floor(Number(req.slot) ?? 0)
+ const slotRaw = Number(req.slot)
+ const slot = Number.isFinite(slotRaw) ? Math.floor(slotRaw) : 0
```
`Number()` 失败返回 `NaN` 而非 `null`/`undefined`，所以 `?? 0` 这条回退分支
**永远不会触发** —— `req.slot` 传 `"abc"` 时 `Math.floor(NaN) = NaN`，
一个 NaN 槽位号被一路传进 bot 的 `select_slot`，表现为「点了没反应」。

### ⑦ 权限表守卫（替代原报告的「删除 accessControl」建议）

新增 `tests/rolePolicyAccessControlParity.test.ts`，把 `rolePolicy` 与
`accessControl` 两套表锁在一起。**当前两表实际一致，测试首跑即通过**；
今后谁单独改动而另一边没跟上，测试立刻红并指出差在哪。

诚实说明：这是**防漂移，不是消除重复**。真正的两表合并应作为独立任务。

### ⑧ agent.json 白名单：从静默陷阱到显式开关

**没有直接让它生效，这是刻意的保守选择。** 三个 agent.json 的 whitelist 是当
**说明文档**写的，与 rolePolicy 差距很大（yak 列 10 项，rolePolicy 允许 27 项）。
若在升级中突然变权威，yak 会当场失去 17 个工具（含 `memory_search`/`todo`），
而配置作者完全不知情 —— 这是「修 bug 修出更大回归」。

采用的语义：
- 默认：禁用集 = rolePolicy 硬边界 ∪ blacklist（**与修复前完全一致**）
- `tools.enforceWhitelist: true` 显式开启后：再叠加 (允许集 − whitelist)，**只收窄永不放宽**
- `lumina doctor` 新增第 12 项检查，把「你写了白名单但它当前不生效」显式报出来

2. **长会话的证据链行为**。`evidenceBridge` 已在单测覆盖，但「被证伪的记忆在
   真实多轮对话中是否真的不再被当成事实讲出来」需要真人体验验证。

3. **磁盘 I/O 稳定性**。评测过程中 K: 盘（HIKSEMI 外接盘）掉线过一次，
   恢复后工作区完好。若发布后收到用户报告的诡异 IO 错误，先怀疑存储层。

## 3.4 最终判断（更新）

> **Lumina 现在可以发 GitHub 了。**

不是因为它比谁强（对着 openclaw 的 39 万星和周均 2,004 次提交，0 到 1,000 star
都要靠内容和分发），而是因为**它现在说的和做的是同一件事**。

修复前的风险不是竞品强，而是「文档吹牛」—— 一个认真读代码的 issue 指出
`ToolDef.toolsets` 从未被读取、47 个工具不可达，会让前面所有「我们特意把别人
比我们强的地方也列出来」的诚实姿态瞬间崩塌。

现在这个风险消掉了。仓库里散落着这样的注释：

- `hybridRecall.ts` —— 「README 吹 RRF 但仓库从来没有过」→ 现在真的有了
- `botRoute.ts` —— 「`?? 0` 是永不触发的死代码」→ 现在修好了
- `registry.ts` —— 「ToolDef.toolsets 曾经完全被忽略」→ 现在读了
- `registrationFlag.ts` —— 「生产环境靠 import 顺序侥幸没炸」→ 现在断开了

**一个愿意把自己的 bug 和判断失误写进注释的开源项目，比一个只有 feature list 的
项目更容易获得信任。** 这也是这个仓库现在最值钱的东西。
