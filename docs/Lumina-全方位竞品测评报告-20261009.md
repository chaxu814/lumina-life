## 一、执行摘要

Lumina 是一个 **工程诚实、创新点明确、但单作者零社区** 的高质量入场项目。它精准卡住了一个目前仍然空着的交集——**「有身体的团队 Agent」**（有形象 + 能干活 + 有主动性 + 记忆就绪）。它对标的 4 个项目里没有任何一个同时做到这四点。

- **最值得肯定**：桌宠绑定真实 Agent 执行状态（4 竞品唯一）· 三 Agent 团队是真代码 · 情绪进入执行层 · 文档罕见地自曝边界 · tsc 严格模式 0 错误、测试占全仓 12%。
- **最大风险**：仅 Windows 实机验证 · 路由不可预测 · 单作者零社区 · IM 仅 Telegram 验证 · 技能生态为空。
- **一句话定位**：它是「一个被三种人格驱动、会真干活、会真记得你、偶尔会犹豫要不要把活派出去的桌宠」，不是「问啥都秒解的全知 AI」。这个定位反而比「全知」更可信。

### 2.3 记忆系统（真实，但深度不及 N.E.K.O）

- ✅ 写入期权威性硬约束：模型自封 `confidence:1.0` 被强制压到 0.6。
- ✅ 五维证据评分 + 7 天半衰期真算（confidence/recency/frequency/corroboration/importance）。
- ✅ BM25 + TF-IDF 余弦，RRF 融合（`hybridRecall.ts`，零依赖）。
- ⚠️ 中文用 **unigram+bigram 字符级分词**，无词典，语义精度有限。
- ⚠️ dense 语义向量**默认关闭**，需外挂 Ollama/embedding 服务。
- ⚠️ 证据链曾是死代码（v3.34 才接通）；模块数（13）远少于 N.E.K.O（35+）。

> 诚实评价：记忆是**入场券，不是护城河**。N.E.K.O 的 `memory/` 是五层流水线、证据强化/质疑双时钟衰减、反思合成、人格晋升——Lumina 的 README 自己也承认这一点。

### 2.4 情绪系统（进了执行层）

底层 3 个连续数值（mood/energy/affinity），带惯性 + 变化率限制 + 基线漂移，映射为 5 种主要可观察表现。真正区别于「换头像」的地方：**情绪影响重试次数**（`delegationManager`），**情绪收紧工具范围**（`emotionGating.ts`，且只能收紧不能放宽——全项目设计最严谨的一处）。

> ⚠️ README 已诚实标注「当前用昼/夜两档开关微调，尚未做连续正弦调制」——不是真昼夜节律。

### 2.5 Computer Use 与安全沙箱

- ✅ 键鼠注入 / OCR / UIA；双层审查（securityGuard 6级×10类 + sandboxRules 32 条规则）；shell 四层沙箱。
- ⚠️ **缺命令归一化层**：base64/反斜杠变体可绕过（如 base64 编码的 `rm -rf /`）。
- ⚠️ macOS/Linux 桌面操控**从未真机验证**。

## 三、四个竞品逐个深度拆解

### 🔴 N.E.K.O —— 唯一 ~85% 重叠的镜像对手

- **定位**：常驻电脑的开源 AI 伙伴（猫娘），能听、能看、会记忆、有主动陪伴。
- **技术栈**：Python 3.11 + FastAPI 后端 + Electron 壳；独立记忆服务器进程。
- **社区**：约 **3,038 ★ · 343 fork · 78 贡献者 · Apache-2.0**，已上架 **Steam + 创意工坊**。
- **形态**：五种 Avatar（Live2D / VRM / MMD / PNGTuber / 猫咪）+ Docker + 移动端内测；有 CUA。
- **它最强 —— 记忆系统**：五层按角色隔离流水线（工作上下文 → 近期记忆 → 事实 → 反思 → 人格记忆）+ `time_indexed.db`。证据双时钟衰减（强化值 / 质疑值各自衰减，净分决定生命周期）；反思合成 → 人格晋升；`hybrid_recall.py` = BM25 + 可选余弦 → **RRF 融合**；强力记忆模式；`/memory_browser` 校对 UI。
- **它比 Lumina 强**：记忆模块 35+ vs 13；分发渠道（Steam）已跑通；移动端内测。
- **它比 Lumina 弱**：**单角色**，无内置多 Agent 团队编排（靠 A2A 调外部 Agent 当「手脚」）；无 Agent 间关系记忆；无分级沙箱；未查到 IM 渠道集成。
- **定性**：唯一真正直接竞争对手。Lumina 应守住「多 Agent + 情绪数值 + 桌宠绑真实状态」，**不要在记忆深度硬拼**。

### 🟠 AIRI —— 形象工程的巨人，记忆上的弱者

- **定位**：开源的 Neuro-sama 复刻 / 「数字生命容器」。
- **技术栈**：pnpm monorepo（40+ packages），Vue.js + TypeScript，Web 优先。
- **社区**：约 **50,220 ★ · 5,025 fork · 205 贡献者 · MIT**。
- **形态**：Web + 桌面（Electron）+ 移动（Capacitor）；多渲染后端（Live2D / VRM 等）。
- **它最强**：同一份 domain 层驱动三端；30+ 模型供应商；6 语言完整 i18n + Crowdin；winget/brew/nix 全渠道分发；WebGPU / WASM 前瞻；已有 `services/computer-use-mcp`（macOS 桌面编排 + 审批队列 + 审计 + 15 个 browser_dom 工具）。
- **它最弱 —— 恰好是 Lumina 的强项**：Roadmap 上 `[ ] Memory Alaya (WIP)` **至今没打勾**（GitHub Issue #879 亦证实）。一个主打「数字生命」的产品，「记得你」那一格还没做完。
- ⚠️ 但要诚实：Lumina 的「记忆领先」只领先一个「本该领先」的东西；AIRI 的 computer-use 已比旧对比表写的「看屏幕」强得多，只是**尚未跨出 macOS**。

### 🔵 openclaw —— 别当对手，当上游标准制定者

- **定位**：「The AI that really does things. Any OS. Any Platform.」
- **技术栈**：TypeScript / Node.js，Gateway 单一控制面 + 5 端原生 App。
- **社区**：**约 391,538 ★ · 82,306 fork · 3,517 贡献者 · MIT**，OpenClaw Foundation（501(c)(3)）治理。
- **赞助方**：OpenAI / GitHub / NVIDIA / Vercel。
- **它最强**：**20–32 个 IM 渠道**；节点配对安全体系（设备身份 + 签名 + 配对审批）；ClawHub 技能市场（700+ 技能）；multi-agent routing；基金会化治理，周均数千次提交。
- **它最弱**：**完全没有形象 / 人格 / 情感层**；记忆刻意做成纯 Markdown。
- **定性**：不是竞争，是必须警惕的上游。渠道能力、技能分发、远程设备接入已被它定义成事实标准。

### 🔵 cc-haha —— 工程参考书

- **定位**：「Local-first cross-platform desktop workspace for Claude Code / agents」。
- **技术栈**：Electron 桌面 + CLI；本质是 **Claude Code 的 GUI 外壳**。
- **社区**：约 **14,933 ★ · 8,603 fork（fork/star=0.58）· 39 贡献者 · MIT**。
- **它最强**：Agent Teams **依赖泳道画布** · **动态 Workflow 现场编排** · **模型 trace 面板** · Worktree 隔离 · 逐文件 diff · 5 级权限 · 8 个 IM 渠道（微信/飞书/钉钉/Telegram/WhatsApp/企微/QQ/Slack）+ H5 远程。
- **它最弱 —— Lumina 恰好越过这条线**：官方桌宠文档原文——「它只是个状态提示和跳转入口，**不能替你批准权限**……宠物**默认关闭**」。且记忆 100% 依赖 Claude Code（自己无记忆层）；商业模式靠 API 中转站赞助（利益绑定）。
- **定性**：服务人群与 Lumina 几乎不重叠。泳道画布、动态 Workflow、模型 trace 是 Lumina 该抄的作业。

## 五、Lumina 相对四项目的优缺点

### ✅ 优点
1. **唯一的「有身体的团队 Agent」**：形象 + 多Agent干活 + 主动性 + 记忆就绪，这个交集是空的。
2. **桌宠绑真实执行状态**：4 竞品唯一，且零 LLM 调用。
3. **「用户只看到一个 Lumina」**：后台三 Agent 协作用户无感（对比 openclaw 要用户自己管 session）。
4. **情绪进执行层**：影响重试次数 + 收紧工具。
5. **反幻觉工程化**：权威性只由 source 定、空产出强制转失败、模板兜底诚实标注。
6. **角色权限硬闸门**：三层 + fail-closed。
7. **文档诚实度罕见**：主动自曝死代码、夸大点、能力边界。
8. **工程底座扎实**：tsc strict 0 错误、测试占全仓 12%、139 工具 0 孤儿。

### ❌ 缺点
1. **生态与社区体量差三个数量级**（0 ★ vs 39 万 ★）。
2. **多端覆盖最弱**：仅 Windows 实机。
3. **分发渠道缺失**：N.E.K.O 已上 Steam。
4. **IM 渠道未验证**：7 适配器仅 Telegram 默认开启。
5. **记忆深度不及 N.E.K.O**，且中文无真分词。
6. **无应用内本地推理**（需外挂 LM Studio）。
7. **多 Agent 可视化弱**：无泳道画布/Workflow/trace。
8. **路由不可预测 + 单作者零社区**。
9. **沙箱有绕过面**：缺命令归一化。

## 六、差异化与创新创意（按可持续性排序）

1. **🥇 桌宠绑定真实 Agent 执行状态**——5 个项目唯一，纯状态机零 token。最难被「加功能」补上的架构性差异。
2. **🥈 「常驻」是架构优势，不是功能优势**——桌宠本来就必须常驻；主动性 + 情绪 + IM 接在一起，得到天然常驻 · 有情绪 · 有团队 · 能干活的远程代理。
3. **🥉 情绪参与系统决策（只收紧不放宽）**——因为若「开心时解锁更多工具」，「诱导她开心」就成了社工攻击面。这个安全前提值得单独讲。
4. **④ 反幻觉的工程化落地**——记忆权威性只由 `source` 定；worker 空产出强制转失败；UI 标注 `来源: llm / 来源: template`。最后一条在开源项目里极其稀缺。
5. **⑤ 精灵表 8×9 UGC**——把做桌宠门槛从「会 Blender」降到「会跟 AI 画图」，全程本地处理。

## 七、普通用户 vs 专业用户 · 模拟体验

### 👤 普通用户
- **上手**：Windows 下载安装包，3 分钟上手；默认云端优先，填好 API Key 即可用，新手无需装本地推理软件。
- **日常体验**：桌宠主动关心；记得你上周说的事；帮定闹钟/搜东西/整理文件/点鼠标；情绪有连续余韵；后台团队有「朋友圈」可旁观。
- **会爽到的**：陪伴感、记忆延续、简单自动化、桌宠演真实工作状态。
- **会踩的雷**：macOS/Linux 不行；技能市场是空的；IM 仅 Telegram 验证过。

### 👨‍💻 专业用户
- **能稳定做好的**：写/改/调试/重构代码（派 Yak，自动跑 tsc+测试）；代码审查与风险评估（热茶并发对抗评审）；跨会话记忆、桌面操控、git、网页抓取、定时任务、MCP、CLI、REST API。
- **会打折的**：模糊任务可能过度编排；需要品味的任务弱；多轮复杂重构；跨文件依赖图展开未经真实任务验证；沙箱有 base64 绕过面。
- **最大爽点**：后台 Yak+热茶流水线「写码→自动审查→自动修复」，你只跟 Lumina 聊。
- **最大顾虑**：单作者 + 0 社区，遇到 bug 只能等作者。
