## 三、核心机制自核口径

### 1. 记忆融合机制

- 五维记忆分层：画像 / 事实 / 反思 / 摘要 / 事件，落本地 SQLite
- 证据链：每条记忆带五维证据评分（7 天半衰期），权威性只由来源（`source`）决定，模型无权自封高置信度；评分当前在 memory_search 工具结果与记忆剧场 UI 生效，自动召回不经它（走混合召回）
- 混合召回：BM25 + 向量余弦 + RRF 真融合，CJK 走无词典分词
- 情绪/关系记忆：亲密度随真实委托演化，affinity 有衰减曲线
- `electron/memory/` 下 18 个模块（存储、召回、证据桥、摘要、关系事件、情绪记忆、联邦导出等）

### 2. 情绪执行层

- 底层只有 3 个连续数值：mood / energy / affinity；向上驱动 5 维表现（开心 / 疲劳 / 专注 / 焦虑 / 好奇）
- 情绪真实参与工具可用性决策：情绪门控**只能收紧工具、不能放宽**，方向由安全约束保证
- 情绪收紧全程留审计日志（`orchestration/emotionAudit.ts`）

### 3. 桌宠绑定真实执行状态

- 六态状态机（idle / working / reviewing / waiting / attention / celebrating），把后台 Agent 的真实任务映射为形象表现
- **零 LLM 调用**（纯函数状态机），3 秒轮询下发，1.2s 防抖，空闲不接管
- 可用 `LUMINA_PET_AGENT_STATE=0` 整体关闭

### 4. 多 Agent 单入口编排

- 三角色硬隔离：主控 / 执行 / 审查；worker 输出架构上不可直达用户
- 委托深度闸：≥3 层委托直接拒绝（AsyncLocalStorage 实现）
- 结果 60s 缓存、输出收敛检测、对抗评审团（多视角并发 + 完整性兜底）、fail-closed

### 5. 安全纵深（命令执行链路）

参数级审查 → 命令规则库 → 权限分级 → 角色闸门 → 审批流 → shell 沙箱，逐层过：

- `securityGuard`：工具参数 / 消息级审查，CRITICAL / HIGH / MEDIUM / LOW 四档严重度，覆盖注入、路径穿越等威胁类别
- `sandboxRules`：shell 命令字符串规则库，BLOCK 档硬拦截（提权、删系统目录、fork 炸弹等），规则库为零依赖纯函数、可单测
- Computer Use 另有 lease 会话锁：自动操作期间用户一碰键鼠即接管

### 6. IM 渠道与远程

- 7 个适配器已接线（Telegram / 微信 / QQ / 钉钉 / Slack / Discord / 本地 Agent 网关），`await import()` 动态装载并被打包器内联
- 现状口径：默认关闭、需自配凭据；仅 Telegram 做过端到端真机验证，其余为「代码已接线、未经真机验证」
- H5 手机远程批准页 `/m`（局域网），权限确认可在手机上完成

## 四、已知短板（自我校正，不回避）

| 说法 | 实际口径 |
|---|---|
| 「跨平台」 | 只有 Windows 实机验证；macOS / Linux 有适配代码但未在真机跑过 |
| 「本地优先」 | 无应用内本地推理，需外挂 LM Studio |
| 「多语言」 | i18n 仅 zh / en |
| 「记忆厚度」 | 记忆模块 18 个、机制完整；但第三方记忆生态为空 |
| 「技能市场」 | `use_skill` / `install_skill` / `skill_run` 已可达，但生态为空 |
| 「人格厚度」 | 每位成员一份身份文件，规模有限；人格融合与自我修正仍在演进 |
