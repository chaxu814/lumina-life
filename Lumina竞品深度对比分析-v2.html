02cc-haha 深度专题（v2 新增）

它是最容易被误判为「竞品」的一个——结论先行：它是开发者工具，不是桌宠竞品。

2.1 一句话定性与三条铁证

cc-haha（Claude Code Haha）是把 Anthropic 的命令行编码 Agent「Claude Code」套进 Electron 桌面壳的本地优先 GUI 工作台，本质是开发者工具，不是陪伴桌宠。
  • package.json:2 直接写 "name": "claude-code-local"、"version": "999.0.0-local"——本体就是 Claude Code 的本地 fork。
  • docs/en/desktop/pets.md:12 官方自述：「It's a status indicator and a shortcut, nothing more. It can't approve permissions for you, and you can't type into it.」（状态指示灯 + 快捷键，不能替你批权限，也不能对它打字。）
  • src/proactive/useProactive.ts 是自动生成的空 Proxy stub，注释明说对应 ant-internal 的 feature() gated 模块——Anthropic 内部模块被剥离。

那个「桌宠」的真相：off-by-default、纯任务状态驱动的 8 列 × 9 行雪碧图小机器人（petSessionModel.ts:23-39），动画状态硬映射为 waiting | running | failed | review | idle 五种，没有 LLM、没有人格、没有情绪变量、不能对话、没有内驱力。这与 Lumina「角色是主语、任务是谓语」的哲学正好相反。

2.2 作者与社区：5.5 个月 14.6k star

作者背景

GitHub 用户 NanmiCoder（profile name「程序员阿江-Relakkes」，新加坡），知名爬虫项目 MediaCrawler（小红书/抖音/B站）作者，有实战开源运营经验，业余维护。

增长与商业化

2026-03-31 建仓 → 09-21 约 5.5 个月 14,662 star / 8,577 fork；09-20 刚发 v0.6.5，约每周一个 release、每天多次 commit。免费开源，靠 API 上游赞助 + 捐赠 + 企业定制。

2.3 它真正做得出色的三个工程点

工程点 1

生产级透明置顶桌宠窗

petWindow.ts：透明无边框 always-on-top 独立窗（384×400）；Windows setShape 做非矩形命中区；拖拽按吉祥物 bbox 夹紧屏幕边缘；面板翻转带 滞回防抖；位置持久化。经 release 验证。

工程点 2

8 平台 IM 远程批权

Telegram/飞书/微信/钉钉/WhatsApp/企微/QQ/Slack；危险权限请求转发到 IM，手机回 yes tbxkq / no tbxkq（5 位随机 ID，FNV-1a、带脏话过滤）；四个来源竞速 first-to-resolve。

工程点 3

完整 Computer Use 栈

27 个 MCP tool schema（24 基础 + 3 Teach）；macOS 原生 Swift daemon 读 AX UI 树（约 60 个 Swift 源文件）；应用白名单三级（read/click/full）+ 前台检测 + session 单活锁 + 冻结坐标配置。

2.4 该偷的 4 条作业，必须避开的 2 个误区

可借鉴
  • 窗口管线：非矩形命中区 / 边缘夹紧 / 翻转滞回 / 位置持久化，直接对照 Lumina 置顶窗实现。
  • IM 远程批权协议：5 位短 ID + 脏话过滤 + yes/no 回令 + 四来源竞速，可用于「手机批准桌宠危险操作」。
  • Computer Use 分层授权：三级白名单 + 前台检测 + 单活锁 + 诚实边界声明，对照补强 cuPermissions.ts（现为 4 级×4 分区）。
  • 自定义桌宠冷启动流程：8×9 动作表规范 + 内嵌 prompt + 本地切片/镜像/归一化，全程本地不耗额度。
要避开
  • 别把角色退化成任务指示灯：它的动画全部是 chatState 的函数。抄窗口工程可以，千万别抄产品哲学——把动画硬绑任务状态会杀死 Lumina 独立人格层 + 情绪变量 + 关系记忆的全部价值。
  • 别被文档骗到有「主动/语音」：useProactive、voice 都是 @generated stub，又被 GrowthBook flag + claude.ai OAuth 双重门控；本体是 Claude Code fork（非完全开源），自行 MIT 声明存在上游许可灰色地带，不宜直接复制代码。

03Lumina vs 每一个项目

逐家三段式：优点 / 缺点 / 根本不同点。每条结论尽量带代码位置。

3.1

Lumina vs N.E.K.O —— 唯一直接同类

Lumina 的优点
  • 多 Agent 社交关系独家：3 独立人格各带 SOUL/PROFILE/AGENTS/MEMORY，agentSocialEngine.ts:45 自发社交（早签/晚回顾），输出只进 Moments 不进用户聊天窗；N.E.K.O 仍是单主人格 YUI + 工具型 brain。
  • 情绪连续态 + 迟滞防抖：9 情绪标签放在 (valence, arousal) 连续平面（emotionCore.ts:56-66），0.06 迟滞阈值防「上句笑下句哭」；N.E.K.O 是离散五维状态机。
  • 内驱力四维推出行为冲动：energy/social/curiosity/comfort 时间衰减（drives.ts:15-24）推出 seekAttention/rest/explore 等；N.E.K.O 内驱力偏「提醒工具」（喝水 30min、防摸鱼冷却）。
  • 同构可测的身体表演：纯 TS 渲染运行时（呼吸 4s、眨眼随机、五元音口型、视线分层、Mixer 多图层），83 个测试文件；N.E.K.O 锁死 Python 3.11，Windows CI 单进程串行 19 分钟。
Lumina 的短板
  • 生态与分发全面落后：N.E.K.O 已上 Steam（appid 4099310，免费）+ 创意工坊 UGC + 一键包/Docker/移动端内测 + 14 内置插件 + 双 SDK + 插件商城；Lumina 是 v0.1.0-preview 未发布。
  • 冷落经济精细度差半档：N.E.K.O「未回应投递权重 1/3（3 次被冷落算 1 次配额）+ 10 分钟内回话权重升 1.0」（pipeline.py:73,75），另有指纹+关键词+bigram 三重去重、topic 候选 60s 成熟、最少 8 轮对话才启动。
  • 记忆工程体量小一档：N.E.K.O memory/ 40+ 文件（recent.py 88KB、facts.py 293KB、embeddings.py 72KB 本地 ONNX + 混合召回）；Lumina 是 6 张 sqlite 表 + TF-IDF/BM25，向量召回需另起本地 embedding server。
  • 投递形态少一类：N.E.K.O 有 chat/toast/动作/mini-game 邀请/情境弹窗 5 类出口；Lumina 统一走 dispatchIntent 到身体表演。
根本不同

N.E.K.O 是「单主角猫娘 + 工具型大脑」，围绕一个 YUI 做活动感知、话题、提醒，押注零配置开箱即用与 Steam 大众分发；Lumina 是「一个角色团住在桌面」，1 主人格 + 2 同事人格自己社交过日子，押注关系与内驱。

两家都要「她主动找你」，但 N.E.K.O 把工程押在「感知你在干嘛 → 找对话题」，Lumina 押在「她自己有情绪欲望 → 身体演出来」。同赛道、两条不同的工程下注。

3.2

Lumina vs AIRI —— 空舞台 vs 活角色

Lumina 的优点
  • 真主动 vs 事件响应：AIRI 没有 cron/定时器驱动的主动 turn，主动性全靠外部事件 spark:notify（Minecraft 事件/浏览器扩展/编排器），用户不发事件她就不说话；Lumina 有 12 类触发源（含 cron/idle/startup/autonomy_tick/daily_paper）。
  • 记忆不做空壳：AIRI memory-pgvector/src/index.ts 仅 24 行、事件回调是空函数，core-character/src/index.ts 是空 export {}，「Memory Alaya」仍 WIP；Lumina 6 张表实打实干（事实/反思/人格/语义 + 证据链）。
  • 情绪门控具体可执行：AIRI 无 busy/勿扰门控，回不回全靠 LLM 自判（builtIn_sparkNoResponse）；Lumina gate.ts:62-91 有场景放行率（game 0.5 / private 0 / idle 0.7）+ 日配额 20 + energy<0.2 退化睡觉。
Lumina 的短板
  • 架构现代度与多端落后：AIRI 是 pnpm monorepo + Vue3，四端（Web PWA / Electron / Capacitor / Godot）+ 五渲染器（Live2D/MMD/Spine/立绘/Three），winget/brew/Scoop 一键装；Lumina 双渲染、桌面单端。
  • 声量差两个数量级：AIRI 49,295 star / Product Hunt featured / Trendshift 上榜；Lumina 未发布。
  • 事件总线设计干净：AIRI spark:command 带 interrupt（force/soft/boolean）+ priority（critical→low）+ intent，guidance.options 是结构化提案包（label/steps/rationale/risk/fallback）；Lumina 跨 Agent 消息没有这么结构化的意图+优先级协议。
根本不同

AIRI 定位「自托管、你拥有的数字生命容器」（复刻 Neuro-sama），卖点是现代技术栈 + 多端 + 能打游戏（Minecraft/Factorio），本质是可扩展的表演容器，记忆与人格核心目前是空的。

一句话：AIRI 是「造好了一个空舞台等人来填角色」，Lumina 是「角色活在台上但舞台只搭了一面墙」。

3.3

Lumina vs openclaw —— 「人」与「事」

Lumina 的优点
  • Lumina 有「人」，openclaw 没有：openclaw 是多渠道 AI 网关，Molty 只是太空龙虾 logo，客户端全是 IM 控制 app，无形象、无情绪状态机、无内驱力、无记忆反思。Lumina 的全部护城河在它体系里整个不存在。
  • 情绪门控是它没有的：openclaw cron 到点就跑、投递到 IM，没有「用户在忙/勿扰」语义门控；Lumina gate 会看 game/private/idle 场景决定打扰概率。
  • 关系记忆 vs 任务记忆：openclaw 记忆 SQLite 为主、无向量无反思；Lumina 有 persona_traits / reflections / affinity 关系层。
Lumina 的短板
  • 工具与渠道生态差一个宇宙：openclaw 161 extensions + 约 50 skills + 30+ 模型 provider + 20+ IM 频道 + ClawHub 市场；Lumina 约 116 工具但 IM 渠道仅 7 个、无第三方插件市场。
  • cron 子系统成熟度差距：openclaw src/cron/ 是 100+ 文件子系统，LLM 可在对话中直接调 cron 工具（642 行）自建/改/删 job，带 heartbeat、pacing 错峰、delivery 校验、session reaper；Lumina cron 只有 3 个工具。
  • 工程治理与体量：390,167 star / 82,057 fork，501(c)(3) 基金会治理，按月发版、一天几十个 commit；Lumina 个人项目未发布。
  • SOUL.md 范式是它先做的：openclaw 明确「AGENTS.md 管操作规则，SOUL.md 管 voice/stance/style」，且有让 agent 自己重写 SOUL.md 的自举机制；Lumina 的 SOUL 三件套是静态本地文件。
根本不同

openclaw 是「你的助手，在你的设备、你的聊天里」——任务型网关，主语是「事」；Lumina 是「你的角色，住在你桌面上」——陪伴型存在，主语是「人」。唯一交集是 IM 投递和 cron 触发。

它只有在某天加上 Live2D 皮肤 + 情绪层时才会变成威胁；在那之前是「降维打工具层、不打角色层」。Lumina 代码里已有 channels/openclaw/openclawClient.ts 把它当通道接入——姿势正确。

3.4

Lumina vs cc-haha —— 主角 vs 指示灯

Lumina 的优点
  • 活的角色 vs 死的状态灯：cc-haha 桌宠无 LLM、无人格、无情绪、不能对话，动画状态 = chatState 的函数；Lumina 有完整内驱力 + 情绪连续态 + 现场 LLM 台词 + 身体表演——物种差异，不是功能差异。
  • 陪伴记忆 vs 开发者记忆：cc-haha 继承 Claude Code 的项目/开发者记忆（User/Feedback/Project/Reference 四类），没有「它记得你们上次聊得什么心情」的关系层。
  • 语音是真能用的：cc-haha voice 是 stub（需 claude.ai OAuth，API-key/自托管用户不可用）；Lumina 本地 Whisper STT（WebSocket 18922）+ edge-tts/IndexTTS 双 TTS + 全双工 barge-in。
Lumina 的短板
  • 桌宠窗口工程细节：cc-haha 有非矩形命中区 / 边缘夹紧 / 翻转滞回 / 位置持久化的 release 级管线；Lumina 窗口层实现细节未查证是否有等价物。
  • Computer Use 分层授权：cc-haha 27 工具 + Teach 引导模式 + 三级白名单 + 前台检测 + session 单活锁 + 冻结坐标；Lumina cuPermissions.ts:29 是 4 级×4 分区，门数类似但缺 Teach 引导、缺 macOS 原生 AX daemon。
  • IM 远程批权：cc-haha 5 位短 ID + 脏话过滤 + 四来源竞速经 release 验证；Lumina 手机端远程批准危险操作的实现未查证。
根本不同

cc-haha 是「给程序员用的 Claude Code GUI」，桌宠是附赠的任务灯；Lumina 是「给想要陪伴的人用的角色」，任务能力是附赠的手脚。二者对「桌宠」二字的理解完全相反。

把 cc-haha 列为竞品是误判；它对 Lumina 的价值纯粹是「可偷的工程作业」（见 §2.4）。

04主动性系统专题（赛道核心战场）

「她会不会主动找你」是陪伴桌宠的生死线。先横向对比管线，再逐条复核 v1 报告的 8 条短板，最后给真实排位。

6.3 四家都没做、只有 Lumina 能做的 3 个差异化方向

01「冷落」会留下关系伤痕，「陪伴」会累积亲密度——曲线可见、可修复

机制：把现在反了的冷落退避正过来——连续 N 天不互动，她的 social 缓慢降级、台词变敷衍、身体表演频率下降（social 衰减 + valence 下移 + gate 打扰概率下调）；一次长对话才逐步「解冻」。unfinishedThread 在记话头、followupTopics 在反思，把「冷落—解冻」做成一条可在 35 个面板之一里可视化的关系温度曲线。

为什么别人没做：N.E.K.O 的冷落权重是配额经济学，不是关系创伤；openclaw/cc-haha 无情绪；AIRI 无定时器。Lumina 是唯一同时有内驱力 + 情绪连续态 + 关系记忆的项目，有条件把「冷落」做成戏剧，而不只是退避参数。

落点：pet/life/drives.ts 加「关系温度」维度；emotionCore.ts 加冷落曲线；新面板可视化。

02三 Agent 背着你开小会，被你撞见时会「尴尬」

机制：扩展 agentSocialEngine.ts——三个 Agent 在你离开时自发聊天（已有 SPONTANEOUS_TOPICS），平时只进 Moments；当你突然回来（idle→active 跳变，复用屏幕在场检测），正在私聊的角色出现「被抓包」身体表演：眼神躲闪、台词切换、表情从放松切到警觉（复用 emotionCore 迟滞）。

为什么别人没做：N.E.K.O 单主角无社交对象；openclaw/cc-haha 多 Agent 是任务分工不背人；AIRI 无「背着用户」的剧场设计。这是三 Agent 社交 + 身体表演 + 在场检测三个独家件的唯一交集。

落点：agentSocialEngine.ts 加「在场感知打断」分支；life/runtime.ts 加「被抓包」表情切换。

03她做的梦 = 你真实生活的潜意识拼贴，醒来用梦影射你

机制：梦境 dreamEngine.ts:285 已接 LLM 且用真实记忆片段（:247-259）——把它与 followupTopics.ts 打通：夜里做梦时把当天事实/对话做成荒诞拼贴；第二天主动台词偶尔用「我昨晚梦到你在 XX 里干 YY」开场（复用 followup 注入 generator.ts:135）。

为什么别人没做：N.E.K.O 的 AutoDream 是开发者记忆整理，不是角色的梦；AIRI 记忆空壳；openclaw 无梦。Lumina 已有 LLM 梦境 + 真实记忆 + 次日主动注入三件套，只差串成「梦→次日台词」的因果链。

落点：dreamEngine.ts 梦醒产出「可引用梦碎片」→ 注入 followupTopics.ts 次日合成。
