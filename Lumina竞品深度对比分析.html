01核心结论

一句话：Lumina 是这五家里唯一把「人格团队 + 连续情绪状态机 + 本地纵深安全沙箱」三件事同时做深的桌面陪伴体；但它也是唯一还没公开发布、没有移动端、没有 UGC 生态的。它不是输给对手功能少，而是输在「没上场」。

TL;DR · 三条判断

① 最直接对手是 N.E.K.O，不是 AIRI。你的记忆系统源码注释白纸黑字写着「借鉴 N.E.K.O 三层模型」（electron/memory/memoryStore.ts:9），而 N.E.K.O 已经在 Steam 免费上架、有五维记忆、五种 Avatar、创意工坊。你追的就是它。

② openclaw 和 cc-haha 根本不在同一个赛道。openclaw 是 Agent 网关基础设施（39 万 star，Peter Steinberger 主导，你的代码里甚至有 channels/openclaw/openclawClient.ts 去接它）；cc-haha 是 Claude Code 的编程工作台，桌宠只是附赠。它们是「手」，你是「心」。

③ 你真正的稀缺护城河是「三 Agent 团队 + 情绪统一层」。别人都是单角色 waifu；你有 Lumina/Recha/Yak 分工，且 pet/life/emotionCore.ts 把五维情绪、valence/arousal、亲密度做了带迟滞防抖的统一换算——这是 AIRI（偏 VTuber/游戏）和 N.E.K.O（偏陪伴但单角色）都没认真做的「关系动力学」。

真家伙
Computer Use 的 Set-of-Mark 网格+zoom 闭环、Windows IL 内核级沙箱、TF-IDF+Ollama/rerank 三级记忆、统一情绪核心——都是真代码，不是 PPT。
半成品
梦境日记/真人秀 LLM 化是刚做的（commit 61338aa），此前是 25 个模板拼接；副人格觉醒是概念验证；VRM 标 beta；语音依赖外部 Python 服务。
最大风险
公开仓库 404（尚未发布）。在你打磨 v0.1 时，AIRI 49k star、N.E.K.O 已上 Steam——「还没上场」本身就是最大的竞争劣势。

04六维能力雷达

只取 6 个维度（雷达超 6 维即失真）。评分 0–10，口径见下：陪伴生命感=情绪/关系/主动性；记忆深度=持久化+检索+反思；Agent工具=工具调用+Computer Use；多端覆盖=可运行端数；生态可扩展=插件/社区/分发；工程成熟=测试+架构+活跃度。分数基于读到的代码与 README，非主观印象。

05市场生态位定位

横轴=工程/生态成熟度（越右越成熟），纵轴=陪伴「生命感」深度（越上越像一个「活着的角色」而非工具）。气泡大小≈社区规模（star）。一眼看清五方站位。

Lumina 落在左上「高陪伴感 · 低成熟度」象限——这是最危险也最有机会的位置：你押对了情感方向，但还没把工程化和分发补上。N.E.K.O 是你最近的右侧邻居（同方向、已商业化）；AIRI 在中上（技术强、陪伴偏 VTuber）；openclaw/cc-haha 在右下（工具属性，不竞争关系）。

06逐家深拆：优点 / 缺点 / 本质不同

vs N.E.K.O（猫娘计划）
2.9k star · Python · Apache-2.0 · Steam 已上架

Lumina 的优点

  • 三 Agent 团队协作（Lumina/Recha/Yak + delegate_chain），N.E.K.O 是单角色，无团队内部分工。证据：electron/team/relationshipDrama.ts 已做团队家庭剧（护主 / 互怼 / 亲密度→审查语气）。
  • 情绪有连续数值层（valence/arousal/affinity）+ 迟滞防抖，N.E.K.O 偏事件驱动的「主动搭话」。
  • Computer Use 做了 OS 级 Windows IL 沙箱（runas 降级 + icacls），N.E.K.O 调 CUA/OpenClaw 走外部。证据：tools/impl/sandboxRules.ts 26 条 7×8 规则 + ipc/sandboxAuditIpc.ts + 侧栏「沙箱玻璃房」面板。
  • TypeScript/Electron 单栈，跨端打包比 Python 分发轻；双协议 AGPL-3.0 OR Apache-2.0 对商业更友好。

Lumina 的缺点

  • 记忆系统明确「借鉴 N.E.K.O 三层模型」，而 N.E.K.O 已进化到五维（工作/近期/事实/反思/人格）+ hybrid_recall + 证据去重，你还在三层。
    → 补强：已落地关系事件记忆层（I4）：electron/memory/relationshipEvents.ts，叙事性事件（承诺 / 共同完成的事 / 你上次难过的原因）可被主动提起，并与梦境日记联动「梦到你们的故事」。
  • N.E.K.O 五种 Avatar（Live2D/VRM/MMD/PNGTuber/猫咪桌宠）+ 动捕，你只有 VRM+Live2D 且 VRM 标 beta。
    → 补强：VRM 情绪动作已接入（五维情绪 → blendShape，pet.vrmExpressive），但口型 / 视线跟随仍在 Live2D，故如实保留 beta。
  • N.E.K.O 用 Realtime API 实时语音，你的语音要外置 Python 服务（edge-tts/indextts/whisper）。
    → 补强：本轮未动（roadmap）：TTS/STT 纯 JS 化仍在排期，当前仍需外置 Python，未夸大为内置。
  • 分发天差地别：N.E.K.O 已上 Steam 免费 + Docker + 移动端内测；你 404。
    → 补强：v0.1 发布 checklist 已产出（见文末「v0.1 落地清单」）；Steam 上架 / 代码签名 / 移动端仍待外部账号与签名，未完成。

本质不同

  • N.E.K.O 是「产品公司打法」：Steam 上架、创意工坊 UGC、猫娘网络社交、跨端记忆同步，重生态和商业化。
  • Lumina 是「极客作品打法」：重内部架构（团队、情绪、沙箱），轻分发和 UGC。
  • 结论：它是你最该对标的对象，但你目前在它「身后半步」的位置。
vs AIRI（Project AIRI）
49.3k star · TypeScript · MIT · 三端

Lumina 的优点

  • AIRI 自己 README 承认 Memory 是 WIP（「Memory Alaya (WIP)」），你的记忆已 SQLite 持久化 + 检索闭环。
  • AIRI 偏「Neuro-sama 式 VTuber/游戏主播」（玩 Minecraft/Factorio/KSP），陪伴的「关系感/亲密度」不是它重点；你把情绪和关系数值做成了核心。
  • AIRI 是 monorepo 大而全（2463 个 ts 文件、几十个 packages），上手门槛高；你是单应用，聚焦「一个人桌面上的陪伴」。
  • 你有三 Agent 团队内互动（群聊/朋友圈/亲密度演化），AIRI 是单角色。

Lumina 的缺点

  • 工程代差巨大：AIRI 有 WebGPU/WASM 浏览器内推理、桌面 CUDA/Metal（candle）、PS5 DualSense 手柄支持、PWA 移动版。
    → 补强：本轮不追广度（定位选择）：聚焦「关系浓度」，WebGPU/手柄/PWA 仍在 roadmap，不假装已做。
  • 多端：AIRI 桌面+iOS/Android( Capacitor)+浏览器全有；你只有桌面。
    → 补强：待外部条件：移动端伴侣仍在 roadmap；本轮只做桌面精简模式（mode.minimal）。
  • 社区：49k star、Crowdin 翻译、Product Hunt、@proj-airi 子项目群；你未公开。
    → 补强：待外部条件：仓库仍 404，v0.1 公开后才谈社区与翻译。
  • Avatar 形态：AIRI 有 VRM/Live2D/MMD/Spine/Tachie 五种渲染 stage，你 VRM 还是 beta。
    → 补强：VRM 情绪已接入但 beta（见上）；MMD/Spine/Tachie 未做，不夸大。

本质不同

  • AIRI 的野心是「数字生命的开源底座」，往游戏、直播、Web 平台扩张；它要做生态。
  • Lumina 是「桌面上一个有脾气的小团队」，往深度关系走。两者不是你死我活，是不同的产品野心。
  • 结论：别和 AIRI 比技术广度，比「关系浓度」。
vs openclaw
390k star · TS+Rust+Go · MIT · 501c3 基金会

Lumina 的优点

  • openclaw 完全没有人格/情绪/形象（README 自述是「assistant in your chats」），它是你可以调用的「手」。
  • 你的沙箱是为「桌宠乱动你电脑」设计的（7级×8类+审批+密钥拦截），它是为「多用户多通道」设计的网关，场景不同。证据：tools/impl/sandboxRules.ts / shellFileWall.ts / src/panels/SandboxPanel.tsx。
  • 你已经在 channels/openclaw/openclawClient.ts 里把它当通道接进来了——这是正确的集成姿势，不是对抗。

Lumina 的缺点

  • 基础设施级差距：openclaw 3.8 万 ts 文件、Rust/Go 混合、20+ IM 通道、企业级部署、501c3 治理、Peter Steinberger 背书。
    → 补强：不正面竞争（定位）：继续把 openclaw 当上游通道接，不自建网关。
  • 你不应该试图自建通道/网关去和它竞争——那是它的主场。
    → 补强：维持现状：channels/openclaw/openclawClient.ts 已接，不扩张通道。

本质不同

  • openclaw = 躯干和神经系统（在哪、怎么连、怎么执行）。Lumina = 灵魂和性格（是谁、什么心情、为什么陪你）。
  • N.E.K.O README 也把 OpenClaw 归为「通用 Agent」，自己只做「关系与陪伴」——和你的定位一致。
  • 结论：把它当依赖/上游，不要当对手。
vs cc-haha（Claude Code Haha）
14.7k star · Bun+TS · MIT · 编程工作台

Lumina 的优点

  • cc-haha 核心是 Claude Code 的 GUI 包装（worktree/diff/审批/MCP 管理器），桌宠只是 README 一行附带功能；你把陪伴当本体。
  • 你有人格/记忆/情绪的完整闭环，它没有——它不关心 AI 「记不记得你」。
  • 你的三 Agent 团队里 Recha 本身就是「毒舌代码审查」，恰好切中 cc-haha 的编程场景，可以差异化做「会陪你写代码的桌宠」。证据：tools/impl/devCompanion.ts（只读 review，写操作走审批）。

Lumina 的缺点

  • 编程能力远不及：cc-haha 直接复用 Claude Code 全能力 + Agent Teams 工作台 + Workflow 编排 + 模型 trace。
    → 补强：已落地方向（I3）：tools/impl/devCompanion.ts 做「懂代码的陪伴」——只读 review diff/commit、吐槽 commit、长时间调试后关怀；定位 cc-haha（纯效率）与 N.E.K.O（纯陪伴）之间的缝，不拼完整工作台。
  • 它有技能市场、视觉 MCP 管理、SubAgent 管理这些开发者向生态；你还在自建。
    → 补强：部分落地：开发者桌宠 companion 已做只读 review；技能市场 / SubAgent 管理仍在自建，未完成。

本质不同

  • cc-haha 是「给程序员用的工具」，桌宠是皮肤；你是「给人用的陪伴」，编程是技能。
  • 两者用户画像有重叠（开发者），但价值主张相反：它要效率，你要关系。
  • 结论：可以做「懂代码的桌宠」差异化，但别去拼编程工作台的完整度。

把「三 Agent 团队」做成独家卖点，而不是三个角色卡
你已有 Lumina/Recha/Yak 分工 + delegate_chain。竞品全是单角色。做「团队内部的关系」：Recha 和 Yak 会互相吐槽、会因为 Lumina 太忙而「护主」、亲密度在三个 agent 之间也演化。N.E.K.O 的「猫娘网络」是外部 AI 社交，你做内置团队的家庭剧——这是 AIRI/N.E.K.O 都没深做的。代码已有 teamMailbox/teamSharedBoard，只差剧本化。
✅ 已落地 · electron/team/relationshipDrama.ts（护主 / 互怼 / 亲密度→审查语气），registerDramaLLM() 已接主进程；未配 LLM 回退模板并标注 source。
2
「会生气的桌宠」——把情绪状态机做成可感知的产品行为
你的 emotionCore 已经有 valence/arousal/疲劳/焦虑 连续数值，但用户大概率感受不到。让情绪影响 UI 和行为：焦虑时 Lumina 说话变短、疲劳时桌宠透明度降低、连续不理她三天后她「冷战」、你主动搭话又「原谅」你。N.E.K.O 有主动性但没有关系恶化/修复的双向动态。这是「生命感」最便宜也最打动人的差异化。
✅ 已落地 · pet/life/emotionExpressions.ts：焦虑→话术变短、疲劳→桌宠透明度/动作变化、连续多天不理→冷战、主动搭话→原谅；开关 emotion.expressiveness / emotion.coldWar。
3
「懂代码的陪伴」——Recha 作为开发者桌宠的生态位
cc-haha 证明了开发者愿意为桌宠花钱，但它的桌宠是装饰。你有 Recha（毒舌工程师）+ shell/git/LSP 工具 + 沙箱。做「写代码时坐在你旁边、会吐槽你的 commit、会在你调试两小时后递一杯水」的桌宠——把 Computer Use 沙箱用在「安全地读你的项目、review 你的代码」上，而不是乱动你电脑。这是 cc-haha（纯效率）和 N.E.K.O（纯陪伴）之间的缝。
✅ 已落地 · tools/impl/devCompanion.ts：安全只读 review diff/commit、吐槽 commit、长时间调试后关怀；默认只读+建议，写操作走审批，不越权改用户代码库。
4
把记忆系统从「借鉴 N.E.K.O」升级成「Lumina 式关系记忆」
你已有事实/反思/人格三层 + 置信度 + 来源。竞品记忆都偏「事实库」。加「关系事件记忆」：记得「你上次难过是因为什么」「你们一起完成的一件事」「她答应过你的承诺」，并在对话中主动提起。N.E.K.O 有五维但偏 CRUD；你做叙事性记忆——不是记得事实，而是记得和你的故事。配合已有的梦境日记，让她「梦到你们的故事」。
✅ 已落地 · electron/memory/relationshipEvents.ts：叙事性关系事件（承诺 / 共同完成的事 / 你上次难过的原因），可被主动提起，与梦境联动；区别于事实 CRUD。
5
「沙箱桌宠」作为安全卖点——主打敢让 AI 动你电脑的人
你的 Windows IL 降级 + 四层防御 + 审批流是真东西，但 README 藏在技术细节里。把它包装成「唯一敢让她真的帮你干活的桌宠」：N.E.K.O/AIRI 都不敢真动用户电脑（怕背锅），你敢。做一个一键「授权她帮我整理下载文件夹」的演示，把沙箱可视化成「透明玻璃房」。这是 Computer Use 赛道里稀缺的「敢」。
✅ 已落地 · ipc/sandboxAuditIpc.ts + src/panels/SandboxPanel.tsx（侧栏「沙箱玻璃房」实时展示拦截/降级/审批）；Sidebar 提供一键「授权她帮我整理下载文件夹」安全演示。
6
双协议 + 自托管叙事，吃「隐私敏感的极客」
你用 AGPL-3.0 OR Apache-2.0、本地 SQLite、AES 加密 key、TF-IDF 零依赖回退。竞品里只有 openclaw 讲隐私，但它没人格。定位「你的记忆只在你硬盘上、不上云、可导出」的桌宠——面向 N.E.K.O/AIRI 用户里担心数据上云的那批人。这是 MIT 协议的 N.E.K.O/AIRI 都没强调的点。
✅ 已落地 · electron/utils/dataExport.ts：本机 SQLite 记忆一键导出/导入 zip（含 manifest + 人读 memory.md，导入按主键去重不覆盖）；onboarding 隐私文案 + 双协议（AGPL-3.0 OR Apache-2.0）说明齐备。
7
先解决「没上场」：砍掉一半功能，先发一个能打的最小版本
这是最重要的一条。你现在 64 工具 + 三 Agent + 双渲染 + 梦境 + 团队社交，摊得太薄。公开发布 v0.1 时只主打三件事：① 一个有情绪会主动找你的桌宠；② 真记得你（本地记忆）；③ 安全地帮你干一件事（整理文件/查资料）。其余全藏在设置里。N.E.K.O 也是先把「猫娘陪你」一件事做到 Steam 好评才扩张。

09风险与短板补强

致命风险：未发布
公开仓库 404。你在打磨 v0.1 的每一周，N.E.K.O 在涨 Steam 好评、AIRI 在涨 star。建议：两周内公开一个最小可玩版，哪怕不完美。沉默打磨是单人项目最大的死因。
技术债：外部 Python 依赖
语音（edge-tts/indextts/whisper）和 embedding server 都要外置 Python 进程。开箱门槛高。建议：TTS/STT 优先走纯 JS 方案（如浏览器 SpeechSynthesis / @xenova 已有 ONNX），Python 降级为高级可选项。
技术债：记忆检索天花板
TF-IDF 是内存重建、无持久化向量索引；中文 bigram 粗糙。N.E.K.O 有 embedding_worker 异步召回。建议：把 @xenova/transformers（你已经装了）真正用成本地 embedding，替代 TF-IDF，避免每次重建词表。
定位风险：贪多嚼不烂
三 Agent + 双渲染 + 梦境 + 团队社交 + Computer Use + MCP + CLI/API——每个单拎出来都不够深。建议：选一个「最被人记住的点」（推荐「会生气的三 Agent 团队」），其他都为它服务。
